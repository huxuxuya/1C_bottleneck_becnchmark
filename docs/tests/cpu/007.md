# 007. Миграция между ядрами

CPU и планировщик · [Каталог и правила прогона](../README.md)

## Методика

Внутри одного NUMA-узла переносить поток с прогретым частным кэшем. Контроль выполняет те же порции на одном ядре.

## Что измерять

Длительность первых порций, число фактических миграций.

## Как читать результат

Кратковременное удорожание вслед за переносом измеряет цену миграции для данного набора.

## Нативное исполнение

`CPU_007_CORE_MIGRATION` снимает текущий CPU ID до и после одинаковых вычислительных порций, считает наблюдённые переходы и отдельно вычисляет медиану порций после миграции. Метрики — `migrationCount`, `medianChunkNs`, `medianPostMigrationChunkNs` и число таких наблюдений. Компонента не закрепляет поток: проба наблюдает естественное планирование и не пытается вызвать миграцию принудительно. Нулевое число переходов означает только, что их не наблюдали в этом коротком окне.

Linux и Windows предоставляют используемый CPU ID API; на macOS проба помечается `Недоступно`. Параметры: `arg1=durationMs` (50–10 000), `arg2=chunkUpdates` (1 000–10 000 000). Автоматический набор — 250 мс и 50 000 обновлений на порцию. Результат сохраняется как `NCPU007C` и `NCPU007S`.
