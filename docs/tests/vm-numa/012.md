# 012. Co-stop в ESXi

Виртуализация и NUMA · [Каталог и правила прогона](../README.md)

> **Статус BSL-only:** описанная здесь прямая метрика требует управления или счётчика ОС/гипервизора, которого BSL не предоставляет. Проект не запускает внешний сборщик и не принимает его пакет. До новой BSL-only методики точный механизм этой проверки не измеряется. См. [границу возможностей BSL](../bsl-only-capabilities.md).

## Методика

Сравнить две конфигурации размера ВМ при том же активном параллелизме и сопоставимом размещении.

## Что измерять

%CSTP, %RDY, работа/с.

## Как читать результат

Изменение co-stop и скорости при контролируемом ready показывает чувствительность к размеру ВМ.

## Текущее состояние

Общий модуль "БенчмаркПроба012CoStopESXi" содержит BSL-код анализа переданных структур и не запускает измерительную нагрузку для этого механизма. Он не считывает OS/гипервизорные показатели и не используется раннером как источник результата. YAxUnit-проверки подтверждают только расчёт на заданных входных данных.

В режиме проекта BSL-only "%CSTP/%RDY и Co-stop ESXi" напрямую недоступна. Методика пока не даёт измерительного результата; до появления соответствующего платформенного API эту проверку нужно пометить «недоступно в BSL» либо отдельно спроектировать поведенческий BSL-прокси с более узким выводом.
