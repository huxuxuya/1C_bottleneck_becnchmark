# 001. Скорость одного ядра

CPU и планировщик · [Каталог и правила прогона](../README.md)

## Методика

Прогреть код и данные, закрепить поток. Повторить зависимую арифметическую цепочку с одинаковой контрольной суммой на каждом доступном ядре.

## Что измерять

Нс/итерацию, CPU-время потока, циклы/итерацию.

## Как читать результат

Устойчивый разрыв между ядрами локализует асимметрию. Учитывать класс ядра и эффективную частоту.

## Расчёт условных МГц внутри 1С

В 7-Zip есть отдельная частотная проба CountCpuFreq. В нативном коде 64 пары зависимых операций сложения и XOR дают 128 учитываемых операций на проход. Результат FreqBench получается из объёма работы и времени, с нормировкой на число потоков. При близкой к одному такту задержке зависимой операции число в миллионах операций/с может приближаться к МГц ядра. Это отдельная проба, у рейтинга сжатия другая методика. [Исходный код 7-Zip, Bench.cpp](https://github.com/ip7z/7zip/blob/main/CPP/7zip/UI/Common/Bench.cpp)

В BSL стоимость итерации в машинных тактах неизвестна. Принцип переносится как «известный объём зависимой работы / прошедшее время». Результат включает исполнение платформой и паузы потока. Для оценки физической частоты по калибровке нужно отдельно обосновать постоянство тактов на итерацию. Такой гарантии между поколениями CPU и версиями платформы нет. Коэффициент 250 нс в старой формуле задаёт шкалу; сам по себе он не даёт точности в аппаратных МГц.

### Нативный вариант через Native API

Исходный C++ измеритель в [документе Native API CPU-пробы](../../native-cpu-probe.md) выполняет известное число зависимых пар `add`/`xor` прямо внутри процесса 1С и выдаёт скорость операций и MHz-эквивалент по принципу 7-Zip. Он не исполняет BSL-цикл, поэтому его результат нельзя смешивать с условными МГц BSL: сравнивать нужно только одинаковый алгоритм и сборку. Это всё ещё оценка по производительности, не показание физической частоты. В команде обработки измеряется клиентский процесс и серверный контекст; в клиент-серверной базе второй результат относится к `rphost`, а файловая база не разделяет эти физические машины. Оба значения исключены из общего балла. Запуск серверного замера проверяется YAxUnit с реальной компонентой.

**Фиксированная проба 001.** Один прогрев и три серии с неизменным числом итераций. Для запуска на сервере вызвать `БенчмаркПробы.Проба001_СкоростьОдногоЯдра(1, 3, 100000)`. В полном прогоне эта строка служит контрольной. [Адаптивная проба 026](../rphost/026.md) выполняет отдельные серии. Обе пробы начинают поле «Детали» с результата в условных МГц, вычисленного из собственных замеров.

    млн итераций/с = N / (1000 × медиана_мс)
    нс/итерацию = медиана_мс × 1 000 000 / число_итераций
    условные МГц BSL = округлить(3000 × базовые_нс_на_итерацию / нс_на_итерацию)

При базе 250 нс формула равносильна умножению измеренных млн итераций/с на 750. Это условный вес одной итерации BSL. Её тело вычисляет `(Состояние * 1103515 + Индекс * 31) % 1000003`. Время включает обработку чисел платформой, управление циклом и паузы планировщика. Поэтому две серии на одном процессоре могут дать разные условные МГц даже при одинаковой физической частоте. У проб 001 и 026 общий цикл и общий вес. Их согласие проверяет повторяемость замера.

По умолчанию шкала определена соглашением: 250 нс/итерацию соответствует 3000 условных МГц. Например, 100 000 итераций за 20 мс дают 200 нс/итерацию и 3750 условных МГц. При 40 мс получаются 400 нс/итерацию и 1875 условных МГц. Значение характеризует скорость одного и того же цикла BSL с учётом планирования и версии платформы. Физическая частота ядра из этого замера не определяется.

При медиане менее 10 мс длительность слишком близка к дискретности таймера. Увеличить число итераций или масштаб полного прогона. До этого результат для МГц — Неопределено. Для привязки к известной опорной точке (Fref МГц, Tref нс/итерацию) на сопоставимой системе коэффициент для отметки 3000 равен Fref × Tref / 3000. Тогда оценка эквивалента равна Fref × Tref / T. Частота из паспорта CPU может отличаться от рабочей частоты при калибровке. При отсутствии проверенной опорной точки использовать подпись «условные МГц BSL». Для собственной шкалы передать положительное базовое время четвёртым параметром пробы либо третьим параметром полного прогона. Явное Неопределено отключает пересчёт. При сравнении стендов использовать одинаковую базу и версию алгоритма. Старые записи с подписью «расч. частота» также содержат пересчёт времени BSL. [Баллы скорости](../../scoring.md)
