# 004. Очередь готовых потоков

CPU и планировщик · [Каталог и правила прогона](../README.md)

## Методика

На фиксированном наборе CPU добавлять вычислителей, оставляя контрольному потоку прежний объём работы.

## Что измерять

Время runnable, длина очереди, работа/с.

## Как читать результат

Зафиксировать первую ступень устойчивого роста времени готовности до исполнения.

## Нативное исполнение

`CPU_004_READY_QUEUE` поднимает заданное число вычислительных потоков и в течение фиксированного окна запускает контрольную работу по срокам с шагом 1 мс. Основной показатель `p95ControlResponseNs` — сумма p95 опоздания старта контрольной порции и p95 её вычислительного времени; доступны обе части отдельно и p99. Это измеряет влияние конкурирующей вычислительной нагрузки на контрольную задачу. Фактическую длину системной run queue и точное время runnable компонент не получает.

Параметры: `arg1=competingWorkers` (1–32), `arg2=durationMs` (50–5 000). Автоматический набор — 2 потока на 250 мс. Результат сохраняется как `NCPU004C` и `NCPU004S`.
