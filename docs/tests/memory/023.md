# 023. Ложное совместное использование линии

Память и кэши CPU · [Каталог и правила прогона](../README.md)

> **Статус BSL-only:** описанная здесь прямая метрика требует управления или счётчика ОС/гипервизора, которого BSL не предоставляет. Проект не запускает внешний сборщик и не принимает его пакет. До новой BSL-only методики точный механизм этой проверки не измеряется. См. [границу возможностей BSL](../bsl-only-capabilities.md).

## Методика

Два закреплённых потока изменяют отдельные счётчики сначала в общей линии, затем в разнесённых линиях.

## Что измерять

Обновления/с, по возможности события когерентности.

## Как читать результат

Ускорение после разнесения при тех же операциях измеряет цену совместного владения линией.

## Текущее состояние

Общий модуль "БенчмаркПроба023ЛожноеСовместноеИспользование" содержит BSL-код анализа переданных структур и не запускает измерительную нагрузку для этого механизма. Он не считывает OS/гипервизорные показатели и не используется раннером как источник результата. YAxUnit-проверки подтверждают только расчёт на заданных входных данных.

В режиме проекта BSL-only "false sharing и события когерентности кэш-линий" напрямую недоступна. Методика пока не даёт измерительного результата; до появления соответствующего платформенного API эту проверку нужно пометить «недоступно в BSL» либо отдельно спроектировать поведенческий BSL-прокси с более узким выводом.
