# Статус реализации проб и диагностик 001–090

[Каталог проверок](README.md) · [Протокол измерений](protocol.md) · [Методика оценки](../scoring.md)

Эта сводка описывает реализованные пробы и границы того, что они подтверждают. Наличие анализатора или тестового сценария не означает, что нужные аппаратные счётчики уже собраны или что проверка выполнена на реальном стенде.

**Граница исполнения проекта — код внутри платформы 1С.** Диагностики выполняются BSL и, для отдельного нативного CPU-замера, компонентой Native API. Внешние OS/гипервизорные счётчики не подменяются измерениями приложения. [Граница возможностей](bsl-only-capabilities.md).

Пробы 001–011 и 026 исполняются BSL-кодом; 001 — контрольная, 002–011 сохраняются как косвенные сигналы, 026 входит в текущий общий индекс. Клиентская проба 027 отдельно измеряет серии вызовов пустого серверного обработчика. Условные МГц 001 и 026 — пересчёт BSL-производительности относительно выбранной калибровки, а не показание аппаратного счётчика.

Модули 012–025 анализируют переданные числовые наблюдения; они не выполняют BSL-сбор и не являются исполнителями этих измерительных механизмов. Внешние пакеты и счётчики проект не запускает. Эти анализаторы намеренно не включены в каталог исполняемых диагностик ниже. YAxUnit проверяет их формулы, но не делает системный механизм измеримым. BSL-таймер имеет разрешение порядка миллисекунды; короткие серии требуют достаточно большой измерительной работы.

## Дополнительный тест CPU через Native API

Кнопка **«CPU: клиент + сервер»** выполняет однопоточную зависимую целочисленную нагрузку в клиентском приложении, затем — через `&НаСервере` в серверном контексте 1С. В клиент-серверной базе второй вызов измеряет CPU рабочего процесса `rphost`. Результаты `CPU_NATIVE_7ZIP` и `CPU_NATIVE_SERVER` записываются под одним ID, поэтому отображаются вместе. Серверная компонента подключается из общего макета перед каждым вызовом; если узел не поддерживает Native API, вторая строка получает статус `Недоступно` с причиной. Оба значения — эквивалент скорости операций в `экв. МГц`, а не физическая частота; они исключены из общего балла. В файловой базе отдельного сервера нет, и оба контекста выполняются локально. См. [карточку нативной пробы](../native-cpu-probe.md).

## Проба 042: последовательный файловый ввод-вывод BSL

Серверная форма напрямую вызывает `БенчмаркПроба042Хранилище.ВыполнитьПрогон()`. Модуль создаёт временный файл через платформу, записывает 64 МиБ псевдослучайного содержимого блоками по 1 МиБ, читает и проверяет три повтора, считает длительность и МиБ/с, удаляет файл. Сохранённые операции показываются в форме; новый регистр `РезультатыФайловойПроб042` хранит одну строку на операцию/повтор, а общий модуль предоставляет выборку и сравнение прогонов по совместимым параметрам. YAxUnit проверяет выполнение трёх циклов, шесть записей с успешными статусами и попарное сравнение точек; тест удаляет свои записи после проверки. Прежний `РезультатыПроб042` сохранён как архив старых точек и не используется новой пробой.

Измерение относится к BSL FileStreams и серверному временному каталогу с влиянием кэшей ОС. Оно не измеряет физическую задержку/IOPS, не гарантирует flush/fsync и не создаёт параллельное давление на чтение. Фактические замеры в репозиторий не сохранены. Детали и границы вывода указаны в [карточке 042](storage/042.md).

## Исполняемый каталог BSL-диагностик 028–090 (без 042)

Модуль `БенчмаркДиагностикиBSL` запускает 62 проверки, которые не анализируют импортированный пакет наблюдений. Каждая запись имеет постоянный трёхзначный номер для порядка и ссылки на методику, а также семантический код (`RPHOST_SATURATION`, `FILE_RANDOM_READ`, `DB_QUERY_BUILD_COST` и т. п.). В регистр `РезультатыПрогонов.КодПробы` сохраняется семантический код, числовой номер не используется как имя проверки.

Для каждого кода есть отдельный серверный тест `Тест_Диагностика_<КОД>`. Ещё один тест выполняет весь каталог и проверяет 62 сохранённые строки, а тест формы выполняет пользовательские команды прогона и диагностики. Текущий полный пакет YAxUnit содержит 102 теста. `build-and-test.sh` проверяет число результатов, failures/errors и ошибки компиляции/инициализации, а не только код завершения клиента 1С.

Проверка от 2026-11-26 на локальной файловой ИБ (`1cv8c` 8.5.1.1529): **102/102 теста, 0 failures, 0 errors**. Набор `BSL-диагностики 028–090` выполнил 63 теста (62 проверки по коду и проверка сохранения всего пакета); сценарий формы тоже прошёл. JUnit-отчёт и журнал доступны после прогона в `build/reports/` и не хранятся в Git.

Текущий состав каталога: **14 прямых измерений BSL**, **17 BSL-прокси** и **31 явно недоступный источник**. Прямое измерение подтверждает только названную BSL-операцию; прокси не выдаётся за CPU Ready, RSS, физические IOPS, SQL waits или другой системный счётчик. Для недоступной проверки пакет сохраняет строку со статусом «Недоступно в BSL», причиной и нулевой измеренной метрикой; это не считается успешным измерением и не набирает баллы. Диагностический пакет в целом не влияет на общий балл оборудования.

## Анализаторы переданных наблюдений 012–025

Эти модули остаются анализаторами входных структур: они рассчитывают показатели по уже собранным наблюдениям и сами не измеряют ОС, гипервизор или NUMA. Их формулы и тесты не засчитываются как выполнение измерительного механизма. Это разделение сохранено намеренно: BSL-only исполнитель не придумывает системные показания, которых платформа не раскрывает.
