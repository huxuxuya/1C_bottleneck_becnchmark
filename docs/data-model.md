# Словарь измерений и модель хранения

[Архитектура](architecture.md) · [Карточки проб](tests/README.md)

Проект контракта версии 1. Пример основного запроса к данным: «Для стенда S, хранилища журнала и чтения QD=1 покажи p95 задержки при фактических 50 МиБ/с фоновой записи. Сравни две версии окружения и раскрой каждый результат до исходной гистограммы». Из этого запроса следуют отдельные сущности для точки нагрузки, попытки, ряда, наблюдения и итога.

## Гранулярность и ключи

| Сущность | Идентичность | Обязательные поля и правила |
|---|---|---|
| Определение метрики в поставке | код метрики + версия семантики | тип наблюдения, единица хранения, границы измеряемого интервала, допустимые статистики, область действия, источник, направление улучшения или «контекст». Изменение смысла создаёт новую версию |
| Спецификация пробы | код из каталога + версия методики + ID и версия реализации | типизированные параметры, обязательные и дополнительные метрики, разрезы, условия валидности, точность и схема первичных данных. Для недоступной реализации видна только методика |
| Документ прогона | UUID | стенд, UTC начала/конца, ссылки на неизменяемые снимки окружения, плана и определений метрик, ревизия приложения, схема импорта |
| Точка плана | прогон + ID точки | проба, реализация, вариант A/B, изучаемый фактор, заданное значение и единица, число исполнителей, seed/снимок данных, режим кэша, бюджет. Несколько осей нагрузки хранить типизированным набором |
| РС ПопыткиПроб | прогон + точка + независимый повтор + попытка | состояние, причина, исполнитель, токен выдачи, фактические параметры, границы фаз, принята ли для сравнения. У одной пары «точка × повтор» не более одной принятой попытки |
| РС РядыИзмерений | ключ попытки + ID ряда | фаза, узел, роль, источник, ресурс и его тип, набор специальных разрезов, единица времени и разрешение часов. Один ряд описывает одну комбинацию этих признаков |
| Поток первичных данных в архиве | ключ ряда + метрика + порядковый номер | монотонное смещение от начала источника, значение либо границы интервала, статус, идентификатор операции при наличии. Для гистограммы — границы корзин, правило включения границ, частоты и число наблюдений. Ссылку на файл хранить в РС АртефактыПопыток |
| РС ПоказателиПопыток | ключ ряда + метрика и её версия + статистика + версия агрегатора | значение, статус наличия, число наблюдений, числитель и знаменатель для отношений, покрытие окна, ссылка на первичные данные. Одна запись — один итог целой фазы этой попытки. Оконные точки графика остаются в архиве |
| Решение о сравнении | ID сравнения + пара точек + метрика + статистика | ссылки на использованные попытки A и B, правило сопоставления, версия алгоритма и бюджета, дельты, различия условий, качество доказательств |

**Представление в 1С.** Код пробы — Строка(3), ссылки на прогон и описание метрики — типизированные ссылки, статусы/фазы/статистики — перечисления либо ограниченные справочники. Счётчики байтов и наносекунд — Число(20,0) для диапазона unsigned 64; производные — Число(28,9) с проверкой диапазона. В обмене с JavaScript целые за пределами точного представления передавать десятичной строкой по схеме поля. У недоступного показателя обязательно отдельное состояние, чтобы числовой ноль по умолчанию в 1С не попал в среднее. Текст ошибки, checksum, план SQL и граф ожиданий имеют собственные типы и не участвуют в числовой агрегации.

## Какие разрезы действительно хранить

| Область | Часто используемые поля отбора | Как пережить следующий прогон |
|---|---|---|
| Стенд | стенд, роль узла, логический ID узла, снимок топологии, версии платформы и СУБД | Имена машин могут меняться. Ключ сравнения использует устойчивый ID либо явно заданное соответствие узлов |
| CPU и память | guest/host, vCPU, физическое ядро и SMT-сосед при известной топологии, NUMA CPU и страниц, размер набора, тип страниц | При неизвестном соответствии сохраняется область наблюдения. Уровни guest и host различаются |
| 1С | ИБ, вид клиента, роль сеанса, идентификатор процесса и время его старта, тип задания, вариант обработчика | PID и номер сеанса используются внутри прогона. Для сравнения между прогонами — роль исполнителя, размещение и профиль работы |
| Диск и СУБД | роль data/log/temp, ID устройства и пути, операция read/write/flush, размер блока, QD, cache mode, движок, вариант плана, класс параметра | Одинаковая буква диска или имя тома недостаточны. Хранить доступную карту том → устройство → общий путь |
| Сеть и клиент | логические концы, направление, маршрут, протокол, число потоков, размер сообщения, режим TLS, тип клиента, граница этапа интерфейса | Клиент → сервер и сервер → клиент образуют разные ряды |
| Эксперимент | вариант, ступень, прогрев/измерение/восстановление, заданный и достигнутый темп, исполнители, повтор, попытка | Фактическая ступень имеет допуск, заданный пробой. Период прогрева доступен отдельно |

Стенд, проба, метрика и время прогона индексируются для истории. Частые локальные отборы используют типизированные поля ряда. Параметры редкой пробы хранятся в версионированном снимке и при необходимости получают индексируемое поле. Тексты SQL, адреса блокировок, ID пакетов и отдельных вызовов остаются в артефактах. Это ограничивает число строк и индексов управляющей ИБ.

## Виды значений и агрегация

| Вид | Что возвращает исполнитель | Как сводить |
|---|---|---|
| Длительность операции | начальная и конечная границы на одних часах либо непосредственно измеренная длительность, статус | p50/p95 по валидным завершённым операциям одной фазы. Метод квантиля и N обязательны. Из интервальной гистограммы показывать точность корзины |
| Монотонный счётчик | начальное и конечное значения, длительность окна, идентичность источника и признаки сброса | скорость = разность / фактическая длительность. Через рестарт или необъяснённый сброс скорость недоступна |
| Мгновенный уровень | значение с отметкой времени, например RSS или очередь | минимум, максимум, изменение. Для среднего по времени указывать способ интерполяции и покрытие окна |
| Суммарная работа | выполненные итерации, байты, строки, завершения и время активного окна | нс/операцию = длительность / выполненную работу. При объединении суммировать числители и знаменатели с учётом перекрытия окон. Полоса параллельных потоков считается за общее прошедшее время |
| Состояние или событие | время, тип, владелец, ожидающий, ресурс, фаза, результат проверки | количество, длительность, граф либо проверка конкретного предиката. Структура ребра графа сохраняется |
| Результат качества | ожидаемая и фактическая контрольная сумма, размещение, план, QD или статус охвата | пригоден / недействителен / недостаточно данных с причиной. Детерминированно повторяемая неверная сумма проваливает проверку |

Общий минимум для управляемого потока — запланировано, отправлено, начато, завершено успешно, ошибка, таймаут, отменено, осталось на границе окна. У операций есть ID и взаимоисключающий конечный исход; состояния очереди на момент среза хранятся отдельно. Позднее завершение после клиентского таймаута сохраняется в серверном ряду. Для нативной пакетной пробы сбор ограничивается счётчиками пакета: фиктивных событий на каждую инструкцию не требуется.

## Обязательные значения первых трёх реализаций

| Проба и код метрики | Исходное значение и единица | Расчёт и разрез |
|---|---|---|
| 026 · bsl.batch.wall_ms | разность часов обработчика, мс на пакет | отдельно по исполнителю, фазе и повтору. Записать вид таймера и разрешение |
| 026 · bsl.batch.iterations | выполненные итерации, шт. | сохранить рядом с заданным числом, типом вычисления и контрольной суммой |
| 026 · bsl.iteration.mean_ns | производная | wall_ms × 1 000 000 / iterations. Медиана этих значений по независимым повторам. Наносекундная единица не повышает разрешение часов |
| 042 · file.bytes | байты, обработанные `DataWriter` или `DataReader` на временном файле, байт | отдельно для операции и повтора; фиксированный объём 64 МиБ |
| 042 · file.elapsed_ms | полное время открытия, последовательных операций и закрытия потока по таймеру BSL, мс | таймер имеет миллисекундное разрешение; хранить исходное целое время, не представлять как наносекундную latency |
| 042 · file.throughput_mib_s | `bytes × 1000 / elapsed_ms / 1 048 576`, МиБ/с | рассчитывать только при положительном интервале; описывает путь файлового API 1С и кэш ОС, не физический носитель |
| 042 · file.checksum_sample | сумма первого, среднего и последнего байта каждого прочитанного блока, байт | сравнить с ожидаемой суммой; ошибка данных делает точку непригодной |
| 062 · lock.acquire.wall_ns | интервал до и после запроса захвата на часах одного исполнителя, пересчитанный в нс | время вызова захвата включает накладные расходы. Сравнить общий и независимый ключи при тех же режимах |
| 062 · lock.wait.duration_ns | длительность ожидания из источника событий, если доступна | по уровню блокировки, ресурсу и паре владелец/ожидающий. Без этого источника для механизма использовать доступные данные о владельце и ставить соответствующий уровень подтверждения |
| 062 · lock.wait.edge | событие с ролью ожидающего, владельцем, режимом, пространством и обезличенным ключом | приложить граф и сведения о транзакциях. Успех контрольного захвата и подтверждение участия обоих сеансов обязательны |

**Пример чтения одной записи.** Учебная точка 026: повтор 2, попытка 1, фаза измерения, серверный исполнитель. При 40 мс за 100 000 проверенных итераций производный итог равен 400 нс/итерацию. Если эталон при сопоставимых условиях равен 320 нс/итерацию, разница составляет +80 нс/итерацию, или +25%. Это разница двух значений. Для решения о регрессии нужны независимые повторы и установленный порог. Числа приведены для проверки формулы.

## Сопоставимость и приёмка

У каждой пробы есть список инвариантов, изучаемая ось и значения, которые лишь поясняют результат. У 042 инварианты — версия BSL-исполнителя, размер файла и блока, последовательный режим и серверный временный путь. Измеряемые операции — чтение и запись; внешняя интенсивность или аппаратный режим кэширования не задаются. У 026 инварианты — алгоритм, размер пакета, тип таймера и режим прогрева. Допуски и правила меняются с версией методики.

Приёмка BSL-пробы проверяет сохранение фактических операций, повторов, параметров, единиц и причины невалидности. Нулевое время не преобразуется в скорость. Повреждённый блок, ошибка потока, таймаут и недостаточное разрешение таймера получают явный статус и не участвуют в оценке. Результат BSL-пробы не дополняется внешними системными счётчиками. Средние по процентилям разных попыток и смешение CPU-времени процесса с временем отдельного вызова исключаются правилами агрегатора.

## Граница детализации

Общие ключи, виды наблюдений и разрезы применяются ко всем 90 карточкам. Для 026, 042 и 062 здесь определены обязательные поля первой реализации и дополнительные свидетельства. Для остальных проб нужные величины перечислены в карточках. До подключения их исполнителя требуется утвердить конкретный источник, единицу, границы замера, доступные разрезы и критерий валидности на целевой платформе.

Для подключённой BSL-пробы 042 новый регистр `РезультатыФайловойПроб042` хранит строку на операцию и повтор: тип операции, объём, длительность в миллисекундах, расчётную скорость, контрольную сумму, статус, путь временного файла и параметры реализации. Старый `РезультатыПроб042` оставлен архивом исторических точек прежнего измерителя; новые BSL-результаты туда не записываются и с ними не сравниваются.
