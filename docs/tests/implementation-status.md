# Статус реализации проб 001–017

[Каталог проверок](README.md) · [Протокол измерений](protocol.md)

Проба 001 и исходные прикладные пробы запускаются внутри конфигурации. Для сценариев 002–011 добавлены исполняемые BSL-измерения, но они дают только косвенные программные сигналы. Для 012–017 добавлены анализаторы внешних замеров ESXi и гостевой ОС; сбор счётчиков, привязка CPU и размещение страниц выполняются вне конфигурации.

| ID | Что делает реализация | Что это не подтверждает |
|---|---|---|
| 002 | Время зависимой арифметической цепочки и четырёх чередуемых цепочек BSL | Машинный код и пропускную способность конкретных инструкций |
| 003 | Опоздание активного цикла относительно срока по часам BSL | Пробуждение спящего потока и время runnable |
| 004 | Сервисное время коротких последовательных вызовов BSL | Очередь готовых потоков и конкуренцию потоков |
| 005 | Число вычислительных порций за фиксированное временное окно | Факт и периодичность применения CPU-квоты |
| 006 | Скорость чередуемых арифметических цепочек в одном потоке | Конкуренцию SMT-соседей |
| 007 | Разброс длительности одинаковых порций BSL | Миграции потока между ядрами |
| 008 | Первую порцию текущего вызова относительно прогретых порций | Факт простоя перед вызовом и выход процессора из idle |
| 009 | Изменение времени одинаковых порций в последовательной серии | Температуру и ограничение мощности |
| 010 | Медиану, P95 и максимум длительности порций | Причину выброса и вклад IRQ/softirq |
| 011 | Расчётную частоту по BSL-нагрузке и калибровке пробы 001 | CPU Ready и ожидание vCPU по счётчикам гипервизора |
| 012 | Сравнение медиан %CSTP, %RDY и работы/с для двух размеров ВМ | Не собирает счётчики ESXi и сам не запускает варианты ВМ |
| 013 | Перекрёстное сравнение одинаковых исполнителей на всех vCPU | Не задаёт affinity и не измеряет длительности внешних исполнителей |
| 014 | Матрица медианного времени чтения для пар CPU/NUMA-узел памяти и штраф удалённого доступа | Не закрепляет CPU и не подтверждает резидентность страниц самостоятельно |
| 015 | Матрица медианной полосы чтения в ГБ/с и на поток для пар NUMA-узлов | Не создаёт потоки и не контролирует размещение потоков/буферов самостоятельно |
| 016 | Сравнение доли страниц на целевых NUMA-узлах и медианы одинакового расчёта после двух вариантов first-touch | Не выполняет инициализацию с CPU-affinity и не снимает карту размещения страниц |
| 017 | Разделение изменений balloon, host swap, guest swap и задержки обхода по трём фазам | Не создаёт давление памяти хоста и не собирает гипервизорные счётчики самостоятельно |

Строки 002–011 имеют статус **«Косвенный сигнал»**: они сохраняются для сравнения, но не участвуют в общем балле и выборе главного узкого места. Анализаторы 012–017 принимают внешние данные, поэтому автоматический прогон их не вызывает и в общем балле они не участвуют. Общий балл рассчитывается только по семи прямым замерам прежнего полного прогона.

Каждая проба 002–017 реализована в собственном общем модуле `БенчмаркПробаNNN…`. Автоматический `БенчмаркРаннер` вызывает BSL-пробы 002–011; анализаторы 012–017 вызываются отдельно с внешними данными. Для повторно используемой арифметики есть служебный модуль `БенчмаркПробыВычисления`. Каждый YAxUnit-сценарий выделен в свой общий модуль `Тест_…` и регистрирует один тест; всего таких тестовых модулей 28.

Для 012 передаются две серии по три или более наблюдений с одинаковыми стендом, размещением, профилем нагрузки и числом активных исполнителей. Вариант содержит `РазмерВМvCPU`, `ЧислоАктивныхИсполнителей`, идентификаторы стенда/размещения/нагрузки и массив `Наблюдения` с полями `CStopПроцент`, `ReadyПроцент`, `РаботаВСекунду`. `БенчмаркПроба012CoStopESXi.СравнитьРазмерыВМ` считает медианы и дельты в процентных пунктах/процентах.

Для 013 `БенчмаркПроба013АсимметрияvCPU.ОценитьАсимметрию` принимает перекрёстную матрицу наблюдений: каждый одинаковый исполнитель должен отработать на каждом vCPU минимум три раза, в отдельных проходах с перестановкой, с одинаковым количеством операций и контрольной суммой. Анализ сравнивает разброс времени на операцию по vCPU и по исполнителям и показывает, за каким фактором следует задержка. Affinity и высокоточный таймер задаёт внешний гостевой измеритель.

Эти шесть проверок не включены в автоматический полный прогон и общий балл: без внешних счётчиков, affinity и подтверждения размещения страниц результаты нельзя получить внутри BSL. YAxUnit проверяет обработку контрольных наборов данных; реальные замеры по карточкам ещё не внесены.

Для 014 `БенчмаркПроба014УдаленнаяNUMAПамять.АнализироватьМатрицу` принимает матрицу `УзелCPU × УзелПамяти` с числом чтений, длительностью в наносекундах, закреплённым CPU, подтверждением резидентности и контрольной суммой. На каждую пару нужны минимум три замера. Результат содержит медиану нс/чтение и штраф относительно локальной диагонали.

Для 015 `БенчмаркПроба015ПолосаNUMA.АнализироватьМатрицуПолосы` принимает матрицу тех же узлов с числом потоков, объёмом байт, длительностью в микросекундах, контрольной суммой и подтверждениями размещения потоков/страниц и размера буфера больше кэша. Анализатор рассчитывает медиану ГБ/с и ГБ/с на поток.

Для 016 `БенчмаркПроба016ПервичноеРазмещение.СравнитьПервичноеРазмещение` принимает варианты однопоточной инициализации и first-touch будущими владельцами. Для каждого варианта нужны распределение ожидаемого и фактического объёма страниц по NUMA-узлам и минимум три длительности одинакового расчёта. Анализатор сопоставляет долю страниц на целевых узлах и медиану длительности.

Для 017 `БенчмаркПроба017ВытеснениеПамятиХостом.АнализироватьДавлениеПамяти` принимает минимум три наблюдения для каждой фазы `До`, `ВоВремя`, `После`. Наблюдения содержат balloon, host swap, guest swap и задержку обхода в нормализованных единицах. Анализатор не смешивает balloon с подкачкой и отмечает возврат задержки после снятия давления.

Все BSL-длительности измеряются `ТекущаяУниверсальнаяДатаВМиллисекундах()` с разрешением порядка миллисекунды. Короткие серии, сравнимые с разрешением таймера, не годятся для выводов; увеличьте размер нагрузки и число повторов. Внешние пробы 012–017 принимают данные от гостевого или гипервизорного инструмента; таймер и фактическое размещение должны быть подтверждены им. YAxUnit проверяет расчёты, контрольные суммы и форму результатов, но не задаёт норматив скорости для конкретного компьютера.

Для подтверждения исходных методик из карточек потребуется внешний сборщик, который снимет таймлайн планировщика и прерываний, affinity и миграции, quota/throttling, температуру/power limit либо гипервизорные CPU Ready/Co-stop — в зависимости от теста и платформы.
