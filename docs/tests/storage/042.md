# 042. Последовательный файловый ввод-вывод средствами BSL

Хранилище · [Каталог и правила прогона](../README.md)

## Назначение

Измерить скорость последовательной записи и чтения временного файла на сервере 1С через `FileStreams`, `DataWriter` и `DataReader`. Проба проверяет конкретный путь от BSL-кода до серверного каталога временных файлов и сохраняет отдельную запись для каждой операции.

Это тест файлового API 1С, а не тест физического накопителя. Платформа не предоставляет этой пробе режим `direct I/O` или принудительный `fsync`; кэш ОС, гипервизора и хранилища может обслужить часть операций. Чтение идёт сразу после записи, поэтому оно может пройти из кэша и не характеризует холодное чтение с устройства. Результаты нельзя называть физической задержкой диска или IOPS устройства.

## Запуск и границы измерения

В обработке «Запуск бенчмарка» нажмите **«Выполнить файловую пробу 042»**. Серверный код получает новое имя временного файла средствами платформы для каждого повтора, записывает туда 64 МиБ блоками по 1 МиБ, затем читает эти данные теми же блоками. Цикл «запись — чтение» повторяется три раза; все временные файлы удаляются после прогона.

Содержимое 1 МиБ буфера заранее заполняется детерминированными псевдослучайными байтами BSL-кодом. Один и тот же буфер повторяется 64 раза, поэтому сжатие внутри блока затруднено, но дедупликация одинаковых блоков на уровне ОС, гипервизора или хранилища всё ещё может повлиять на результат. Подготовка буфера и создание результата регистра находятся вне измеряемых интервалов. Интервал записи включает открытие потока, 64 вызова записи и закрытие; интервал чтения включает открытие, 64 вызова чтения и закрытие. При чтении сверяются размер каждого блока и сумма трёх выбранных байтов каждого блока.

Путь берётся из временного каталога процесса сервера 1С. В форме показывается имя последнего использованного файла; файл уже удалён к моменту показа. Эта проба не позволяет выбрать том и не затрагивает файлы базы, журнала СУБД или другие постоянные файлы.

## Сохраняемые показатели

| Показатель | Расчёт и смысл |
|---|---|
| `ОбъемБайт` | Число байтов, прошедших через чтение или запись |
| `ДлительностьМс` | Длительность полного интервала операции по таймеру 1С с миллисекундным разрешением |
| `МиБайтВСекунду` | `объём байт × 1000 / длительность мс / 1 048 576`, то есть МиБ/с |
| `КонтрольнаяСумма` | Сумма первого, среднего и последнего байта каждого блока; при чтении сравнивается с ожидаемой суммой |
| `Статус`, `Комментарий` | Успех, ошибка чтения/записи, повреждение данных, недостаточное разрешение таймера или пропуск парной операции |

Таблица формы показывает повтор, операцию, объём, время, скорость и статус. Результаты автоматически записываются по одной строке на операцию в `РезультатыФайловойПроб042`; `ПолучитьТочкиПрогона()` возвращает их для повторного просмотра, а `СравнитьПрогоны()` сопоставляет одинаковые операции одинаковых повторов при совпадающем ключе методики. Старый регистр `РезультатыПроб042` оставлен для сохранности исторических записей прежней методики и новым исполнителем не используется.

## Интерпретация

- Стабильные результаты показывают повторяемую скорость файловых потоков 1С на текущем серверном временном пути.
- Разница между чтением и записью характеризует поведение этих двух операций через платформу и текущий путь хранения.
- Резкое изменение между повторами — повод повторить прогон и проверить загрузку сервера, но само по себе не определяет источник паузы.
- Ошибка контрольной суммы означает, что измерение нельзя считать успешным.
- Нулевой интервал или интервал ниже разрешения таймера не преобразуется в скорость.

Успешная проба не доказывает, что данные дошли до физического носителя: закрытие файлового потока не заменяет гарантированный `fsync`. Она не воспроизводит параллельное давление записи на чтение, глубину очереди, случайные операции, spill СУБД или восстановление после снятия нагрузки. Для этих причин потребуются отдельные BSL-сценарии с явно доступным путём/данными; если платформа не раскрывает нужный аппаратный счётчик, тест должен сообщить «не измеряется средствами BSL», а не подменять его оценкой.

Сравнение конфигураций полезно только при одинаковом коде пробы, размере файла и блока, а также при понимании, какой каталог временных файлов использует каждая серверная установка. Регистр не смешивает этот показатель с общим баллом.

## Реализация

Исполнитель находится в `БенчмаркПроба042Хранилище.ВыполнитьПрогон()`. Он не запускает внешние программы, не читает импортный пакет и не принимает JSON. Все измерения выполняются на сервере 1С, а точки сохраняются непосредственно в информационный регистр.

Фактические замеры в репозиторий пока не внесены.
