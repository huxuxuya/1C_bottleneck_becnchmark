# 024. Синхронный reclaim

Память и кэши CPU · [Каталог и правила прогона](../README.md)

> **Статус BSL-only:** описанная здесь прямая метрика требует управления или счётчика ОС/гипервизора, которого BSL не предоставляет. Проект не запускает внешний сборщик и не принимает его пакет. До новой BSL-only методики точный механизм этой проверки не измеряется. См. [границу возможностей BSL](../bsl-only-capabilities.md).

## Методика

Увеличивать набор в группе с ограниченной памятью. Разделить выделение адресов и первое касание страниц.

## Что измерять

Задержка выделения и касания, direct reclaim, memory PSI.

## Как читать результат

Порог, после которого сам выделяющий поток тратит время на освобождение памяти, задаёт предел набора.

## Текущее состояние

Общий модуль "БенчмаркПроба024СинхронныйReclaim" содержит BSL-код анализа переданных структур и не запускает измерительную нагрузку для этого механизма. Он не считывает OS/гипервизорные показатели и не используется раннером как источник результата. YAxUnit-проверки подтверждают только расчёт на заданных входных данных.

В режиме проекта BSL-only "reclaim, cgroup и PSI" напрямую недоступна. Методика пока не даёт измерительного результата; до появления соответствующего платформенного API эту проверку нужно пометить «недоступно в BSL» либо отдельно спроектировать поведенческий BSL-прокси с более узким выводом.
