# 006. Конкуренция SMT

CPU и планировщик · [Каталог и правила прогона](../README.md)

## Методика

Один и тот же второй поток закрепить сначала на SMT-соседе контрольного, затем на отдельном физическом ядре.

## Что измерять

Итерации/с первого потока, частота.

## Как читать результат

Разница измеряет чувствительность к совместному использованию ядра при подтверждённой физической топологии.

## Нативное исполнение

`CPU_006_SMT_COMPETITION` проверяет доступную топологию и закрепляет контрольный и конкурирующий потоки. Сравнивает throughput контрольной нагрузки без соседа, при вычислении на SMT-соседе и при вычислении на отдельном физическом ядре. Основной показатель `smtThroughputPercentOfBaseline`; в подробностях есть выбранные CPU и скорости всех вариантов. Проба возвращает `Недоступно`, если ОС не раскрывает нужную топологию или не разрешает привязку. Linux и Windows поддержаны; macOS не предоставляет используемую компонентой привязку.

Параметр `arg1=durationMs` (50–5 000); автоматический набор — 250 мс на вариант. Проверяется фактическая привязка потоков к выбранным логическим CPU. Результат сохраняется как `NCPU006C` и `NCPU006S`.
