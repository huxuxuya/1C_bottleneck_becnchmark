# 042. Влияние записи на чтение

Хранилище · [Каталог и правила прогона](../README.md)

## Назначение

Измерить, как заданный темп фоновой записи влияет на задержку случайного чтения с QD=1 на том же файловом пути. Результат — кривая фактически достигнутой записи и p50/p95/p99 чтения, включая покой и восстановление.

Это изолированная проба файлового пути. Она не обращается к файлам базы, журналам СУБД или рабочим каталогам 1С и не запускается из BSL. Исполнитель пишет только во временные файлы с собственным UUID в явно указанном каталоге.

## Требования к стенду

- Linux и `fio`; текущий исполнитель использует `psync`, `direct=1`, один синхронный читатель и один синхронный писатель.
- `--work-dir` должен быть отдельным каталогом на том пути, который требуется измерить. Каталог уже должен существовать. Не указывайте корень диска, каталог базы или каталог приложения.
- `--file-size-gib` задаётся явно и применяется к каждому из двух файлов. Выберите размер больше кэшей, которые хотите исключить, кратный 1 МиБ, и убедитесь, что на томе хватит места. Файлы предварительно записываются, поэтому начальное выделение места не входит в измеряемые интервалы.
- Нужны минимум три повтора. Порядок ступеней циклически сдвигается между повторами, чтобы одна и та же ступень не всегда измерялась первой или последней.
- Результат JSON храните вне измеряемого каталога. Скрипт записывает его только после серии.
- `direct=1` обходит кэш страниц гостевой ОС, но не гарантирует обход кэша RAID-контроллера или массива. Файлы, блок, режим I/O, версия fio и устройство записываются в пакет.

## Запуск

```sh
RUN_ID="$(uuidgen)"
python3 tools/probes/042/run_probe_042.py \
  --work-dir /mnt/benchmark-test \
  --output "/var/tmp/probe-042-${RUN_ID}.json" \
  --run-id "$RUN_ID" \
  --file-size-gib 8 \
  --write-rates-mib-s 8,16,32,64 \
  --duration-seconds 20 \
  --ramp-seconds 5 \
  --repeats 3
```

Скрипт выполняет для каждого повтора одиночное чтение, затем каждую ступень параллельной записи и чтения, а после каждой ступени — чтение восстановления без фонового писателя. Порядок ступеней сохраняется в пакете. `randseed` детерминированно выводится из повтора, фазы и целевого темпа: соответствующие точки при совпадающей версии fio получают один шаблон доступа, а разные фазы — разные шаблоны ([fio `randseed`](https://fio.readthedocs.io/en/master/fio_doc.html#cmdoption-arg-randseed)). Конверт содержит каноническую JSON-полезную нагрузку и её SHA-256; 1С пересчитывает хеш перед импортом. Полезная нагрузка включает сырые fio JSON+ по каждой фазе, точные параметры и снимок тома. При ошибке сохраняется частичный пакет и точка с причиной. При `--keep-files` остаются только файлы данной попытки; по умолчанию они удаляются.

## Метрики и валидность

| Поле пакета | Смысл |
|---|---|
| `target_write_rate_Bps` | Запрошенная ступень записи, байт/с |
| `random_seed` | Seed потока случайных смещений, общий для сопоставимой точки на разных стендах |
| `completed_write_bytes` | Запись, засчитанная fio на фазе измерения |
| `window_elapsed_ns` | Измерительное окно чтения из поля `read.runtime` fio, без lead-in `ramp_time` |
| `write_window_elapsed_ns` | Отдельное измерительное окно писателя из поля `write.runtime` fio |
| `actual_write_rate_Bps` | `completed_write_bytes × 1 000 000 000 / write_window_elapsed_ns`, в байт/с |
| `read_p50_ns`, `read_p95_ns`, `read_p99_ns` | Completion latency чтения fio, наносекунды |
| `read_qd_actual` | Фактическая глубина чтения 1: один `psync` reader не может держать более одной незавершённой операции |
| `read_iops` | IOPS читателя в измерительном окне |
| `read_errors`, `write_errors` | Ошибки операций fio |

Точка валидна только если есть положительное измерительное окно и p50 ≤ p95 ≤ p99, QD чтения равен 1 и нет ошибок. Для pressure-точки также обязательны завершённые байты записи и положительный измеренный темп. Время берётся из runtime соответствующей fio-операции: `ramp_time` является lead-in и увеличивает общее время задания, поэтому его нельзя вычитать из общего `job_runtime` ([документация fio](https://fio.readthedocs.io/en/latest/fio_doc.html#cmdoption-arg-ramp_time)). Сопоставлять нужно одинаковые размер файла, размеры блоков, `direct` и версии fio. Устройство у сравниваемых машин может отличаться; его идентификатор сохраняется в отчёте. Используйте фактический, а не заданный темп записи на оси кривой.

## Импорт и сравнение в 1С

Общий модуль `БенчмаркПроба042Хранилище` принимает пакет через `ИмпортироватьПакетJSON(ТекстJSON)` или `ИмпортироватьПакетИзФайла(ПутьКФайлу)`. В форме запуска бенчмарка укажите путь, доступный серверу 1С, и выберите «Импортировать пакет 042». Идентификатор прогона заполнится из пакета; поле также можно задать вручную и нажать «Показать кривую 042» для повторного просмотра.

Каждая baseline, pressure и recovery-точка хранится отдельной строкой регистра `РезультатыПроб042`, включая фактический seed случайного доступа. Повторная доставка того же SHA-256 пропускает уже записанные точки; другое содержимое под прежним ключом прогона/точки отклоняется. Несколько новых строк фиксируются транзакционно. Форма показывает числовую кривую по точкам. Для программной выборки используйте `ПолучитьТочкиПрогона(ИдентификаторПрогона)`, для попарного сравнения pressure-точек с теми же ID и повторами — `СравнитьПрогоны(ИдентификаторПрогонаA, ИдентификаторПрогонаB)`.

Проба диагностическая и в общий балл не входит. Вывод о границе делают по кривой и бюджету p95, заданному профилем обследования: указывают последнюю валидную ступень в бюджете и первую валидную ступень за ним. Recovery-точки показывают возврат p95 к baseline после снятия записи. Если заданная ступень не достигнута, её нельзя трактовать как проверенный предел.

## Уровень доказательности

`fio` непосредственно измеряет поведение файлового пути гостевой ОС и достигнутую нагрузку. Одновременный рост p95 чтения на ступенях записи локализует конкуренцию в общем пути. Чтобы назвать причиной конкретный RAID, виртуальный диск, SAN, гипервизорный слой или накопитель, сопоставьте пакет с телеметрией соответствующего слоя и картой тома.

## Результаты прогонов

Фактические замеры в репозиторий пока не внесены.
