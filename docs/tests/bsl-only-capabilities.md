# Граница измерений BSL и Native API

[Каталог проверок](README.md) · [Протокол измерений](protocol.md) · [Статус реализации](implementation-status.md)

## Правило исполнения

Основные диагностические сценарии выполняются встроенным языком и объектами платформы 1С. Отдельно выполняется нативная CPU-проба на C++ через официальный Native API 1С. Ни BSL-сценарии, ни эта компонента не запускают shell-команды, сторонние утилиты или внешний агент и не импортируют сформированные ими измерительные пакеты.

Native API-компонента собрана для семи архитектур. Клиентский smoke-тест на 1С 8.5.1/macOS x86_64 подключил её, создал объект `AddIn.CpuFrequencyProbe.CpuProbe`, выполнил замер и проверил JSON. Кнопка **«CPU: клиент + сервер»** сначала асинхронно измеряет клиентский процесс, затем вызывает серверную форму `&НаСервере`, повторно подключает компоненту и выполняет замер в серверном контексте. Две строки (`CPU_NATIVE_7ZIP`, `CPU_NATIVE_SERVER`) сохраняются под одним ID и не входят в общий балл. Форма YAxUnit с реальным серверным вызовом прошла в локальной файловой ИБ; отдельный кластерный `rphost` требует проверки на клиент-серверном стенде. Если компоненту на сервере подключить нельзя, серверный результат записывается как `Недоступно` с причиной. Отдельный клиентский клик не входит в пакетный прогон, поскольку первая установка может потребовать подтверждения пользователя. Исполняемые пробы 001/026 остаются BSL-реализациями. Методика, сборка и ограничения описаны в [документе Native API CPU-пробы](../native-cpu-probe.md).

Это правило задаёт способ исполнения, но не даёт BSL доступ ко всем аппаратным и системным счётчикам. Каждая методика обязана выбрать один из трёх статусов источника:

| Статус | Что означает |
|---|---|
| **Прямое измерение BSL** | Платформа выполняет полезную работу, а сценарий измеряет её объём, длительность, результат и ошибку |
| **Прямое измерение Native API** | Нативный код внутри процесса 1С выполняет известный объём операций и измеряет время монотонными часами |
| **BSL-прокси** | Измеряется эффект на времени или результате операции 1С; конкретный внутренний механизм не подтверждён |
| **Недоступно в BSL** | Нужный счётчик или управление размещением платформа не предоставляет; значение не подменяется догадкой |

Прокси нельзя подписывать именем системного счётчика. Например, задержка вычислительного вызова под нагрузкой не равна CPU Ready, steal time, IRQ-времени или ожиданию потока в очереди.

## Что можно измерять напрямую

- Длительность BSL-вызова, пакета или серверного round trip на границах, которые контролирует код.
- Выполненные итерации, обработанные строки и байты, контрольные суммы, ошибки, таймауты и фактический результат операции.
- Длительность и скорость последовательной файловой операции через `FileStreams`, с учётом пути 1С и кэшей нижних слоёв.
- Время выполнения запроса 1С и количество строк, которые вернул сценарий. Это не раскрывает автоматически фактический план, физические чтения и ожидания СУБД.
- Ожидание известной операции 1С в координируемом многосессионном BSL-сценарии, если платформа даёт сценарию выполнить и проверить это условие.

## Где BSL даёт только прокси или не даёт источника

| Область | BSL-наблюдение | Что нельзя утверждать по нему одному |
|---|---|---|
| CPU и планировщик | Скорость одинаковых BSL-порций; скорость нативной зависимой add/xor цепочки при подключении Native API-компоненты | Физическую частоту CPU, user/sys time, run queue, runnable wait, миграции, IRQ/softirq, SMT-соседство и CPU quota |
| Виртуальная машина | Изменение времени BSL-работы при разных контролируемых размерах нагрузки внутри гостя | CPU Ready, Co-stop, steal, хостовую конкуренцию и фактическую привязку vCPU |
| NUMA и память | Время обхода BSL-структур разных размеров и изменение скорости под BSL-нагрузкой | Физическое размещение страниц, локальность NUMA, page walks, LLC misses, DRAM-трафик, ballooning и host swap |
| Файловое хранилище | Байты и время потока 1С на серверном временном пути | `direct I/O`, гарантированный flush/fsync, физические IOPS/latency, очередь устройства и отдельный том data/log/temp без доступного пути |
| СУБД и транзакции | Время запросов 1С, длительность транзакции, подтверждённое ожидание управляемой блокировки | Фактический план и физические reads, temp spill, lock graph движка СУБД и точную внутреннюю причину ожидания |
| Сеть | RTT и скорость контролируемого обмена, если сценарий сам выполняет протокольный запрос | Потери пакетов, retransmit, MTU, NIC queue, маршрут каждого сегмента и сетевой аппаратный сброс |
| Процесс 1С | Число и длительность известных вызовов; изменение времени при контролируемом числе фоновых заданий | RSS/PSS рабочего процесса, системные context switches и внутреннее распределение CPU без BSL-источника |

Наличие BSL-прокси полезно для поиска деградации: оно указывает, что контролируемая операция стала медленнее или менее стабильной. Оно само не различает несколько причин с одинаковым внешним эффектом. Методика должна назвать различающий следующий BSL-эксперимент или закончить выводом «причина не определяется средствами BSL».

## Требования к карточкам тестов

Для каждой проверки указываются исполняемый модуль 1С, рабочая нагрузка, таймер и его разрешение, исходные единицы, параметры, проверка результата, статус источника (прямое измерение / прокси / недоступно), возможные альтернативные причины и точный предел вывода. В карточке «планируется» не означает «уже реализовано».

Системный счётчик, который недоступен платформе и компоненте, нельзя оценивать баллами или показывать как будто он измерен. Скорость операций Native API — это отдельная оценка вычислительной производительности, а не физический MHz или замена счётчиков ОС/гипервизора.

## Пример: проба 042

042 записывает и читает BSL-данные через серверные файловые потоки, считает объём, миллисекунды и МиБ/с, сверяет выбранные байты и удаляет временный файл. Она измеряет интерфейсный путь 1С к серверному temp-каталогу. Кэширование ОС и файловой системы остаётся частью наблюдаемого пути; никакого вывода о физическом диске, fsync или конкурентном влиянии записи на чтение проба не делает.
